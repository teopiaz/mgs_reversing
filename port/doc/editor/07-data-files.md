# Data files

The editor relies on a handful of generated files alongside the binary.
This page enumerates each, where it comes from, and what its rows mean.

## `port/editor/data/<stage>_actors.tsv`

Per-stage actor placement table — what populates the Actors tab and
the cube/model markers in the 3D view. One row per spatial actor.
Tab-separated, no header line. Nine columns:

| # | Column        | Example               | Notes |
| - | ------------- | --------------------- | ----- |
| 1 | `type`        | `WATCHER`             | Symbolic actor type from the GCL `chara &TYPE` literal. Resolves to a 16-bit hash via `port/gcl_tools/mgs_names.py`. |
| 2 | `instance`    | `$s:1465`             | Per-instance id (also a hashed-string literal in GCL). |
| 3 | `x`           | `-9500`               | World X (PSX units, int32 in the file but always fits in int16). |
| 4 | `y`           | `0`                   | World Y. PSX +Y is down. |
| 5 | `z`           | `-12250`              | World Z. |
| 6 | `color`       | `#8B999A`             | Suggested marker colour — derived from the type name (so all WATCHERs share a colour). |
| 7 | `proc`        | `sub_7ECB`            | Name of the GCL proc that emits this `chara` line. Useful for grepping back into `scenerio.gcl`. |
| 8 | `rot`         | `b:16` or `[306, 3010, 0]` or empty | Rotation. `b:N` (single byte 0..255 = 0..360°) is the common form; some chara types use a 3-int vector. |
| 9 | `from_demo`   | `0` or `1`            | `1` if the row was extracted from `demo.gcl`, `0` from `scenerio.gcl`. |

Generated by:

```
python3 tools/build_editor_data.py
```

That walker iterates `port/overlays/<stage>/scenerio.gcl` and
`port/overlays/<stage>/demo.gcl` (when present), feeds them through
`port/gcl_tools/gcl_parser.py`, and emits one TSV per stage. Skipping
stages without a decompile is fine — the editor just shows `0 actor
markers` for those.

The editor's `Save` button rewrites this same file — anything you've
edited in the *Selected* card lands here on save. Round-tripping
through the disk is supported (Reload picks up external edits).

## `port/editor/data/<stage>_actors.json`

Same data as the TSV, written alongside it. The JSON form preserves
all options on each `chara` line (not just `pos` and `rot`), which
makes it useful for external grep / analysis tools and for debugging
the extractor. The editor itself only reads the TSV.

## `port/editor/extra_stages/<name>/datacnf.bin`

A complete custom-stage blob produced by `tools/import_stage.py`.
Layout matches the engine's DATACNF format (see
[06-asset-formats.md](06-asset-formats.md)). The editor's libfs scans
this directory at startup and appends each subdirectory's stage to
the picker.

## `port/editor/extra_stages/<name>/manifest.json`

Records the import-time settings so the Reimport button can re-run the
same build. Schema:

```json
{
  "name": "s99a",
  "obj":       "port/editor/assets/s99a/s99a.obj",
  "texture":   "port/editor/assets/s99a/s99a.png",
  "collision": "port/editor/assets/s99a/s99a_collision.obj",
  "scale": 100.0
}
```

Relative paths are resolved from the repo root. Edit by hand if you
move source files around — the importer reads the manifest before the
CLI args, so manually-tweaked fields persist across reimports.

## `port/editor/imgui.ini`

Standard ImGui layout cache (window positions, collapsed-state per
window). Created automatically on first run. Safe to delete to reset
the layout.

Do **not** check this into git — it's per-user state. The editor's
`.gitignore` already lists it.

## Source assets — `port/editor/assets/<name>/`

Checked-in source for any custom stages distributed with the repo.
For the demo `s99a`:

```
port/editor/assets/s99a/
  s99a.obj                  # visual mesh — 100×100×100 cube
  s99a.mtl                  # references s99a.png as map_Kd
  s99a.png                  # 256×256 checkerboard
  s99a_collision.obj        # 100×100 floor quad (two triangles)
```

Authored by hand and importable with the standard `import_stage.py`
flags. Useful as a smoke test when verifying changes to the importer.

## Build artifacts (gitignored)

| Path                       | Reason                                         |
| -------------------------- | ---------------------------------------------- |
| `port/editor/obj/`         | C/C++ object files                             |
| `port/editor/editor`       | Final binary                                   |
| `port/editor/imgui.ini`    | Per-user UI state                              |
| `port/editor/extra_stages/` | Generated DATACNF blobs                       |
| `port/editor/screenshot-*.ppm` | Output of the Screenshot button            |

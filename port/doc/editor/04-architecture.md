# Architecture

## File layout

```
port/editor/
  Makefile                  # builds the port first, then links the editor
  main.c                    # SDL/GL bootstrap, frame loop, input poll
  ed_loader.c               # FS_LoadStageRequest + GV cache scan + unload
  ed_camera.c               # free-fly camera (DG_LookAt)
  ed_render.c               # KMD walker, world-axes gizmo, projection helpers
  ed_hzd.c                  # HZD wireframe overlay + selection helpers
  ed_actors.c               # actor TSV load/save, KMD lookup, ray-pick
  ed_ui.cpp                 # ImGui inspector (Scene/Camera/Actors/HZD)
  editor.h                  # public-ish API between the .c/.cpp modules
  editor_stubs.c            # symbols normally provided by the excluded port objects
  data/
    <stage>_actors.tsv      # one per stage, generated by tools/extract_gcl_actors.py
    <stage>_actors.json     # same data in JSON for external tools
  extra_stages/             # gitignored; holds custom stages built by the OBJ pipeline
    <name>/
      datacnf.bin
      manifest.json         # what the Reimport button re-feeds to the importer
  assets/                   # checked-in source assets for demo levels
    s99a/{s99a.obj,s99a.mtl,s99a.png,s99a_collision.obj}
```

The editor binary is one self-contained executable; nothing in the main
port (`port/mgs`) is needed at runtime.

## Linking strategy

The Makefile globs `port/obj/*.o` and links **everything except**:

- `main.o`           — replaced by the editor's own `main`
- `main_game.o`      — game tick is irrelevant for inspection
- `imgui_debug.o`    — replaced by `ed_ui.cpp`
- `test_server.o`    — game-only test harness

That brings in:

| From port library  | What we use                                    |
| ------------------ | ---------------------------------------------- |
| `port/libdg/*.o`   | `gl_renderer`, `kmd_loader`, `pcx_loader`, `vram`, all `libdg_*` engine code |
| `port/libfs/*.o`   | ISO mounting, STAGE.DIR parsing, stage loading |
| `port/libgv/*.o`   | GV cache (KMD/HZD pointers), strcode hashing, allocator |
| `port/libhzd/*.o`  | HZD pointer fixups, collision queries (unused but linked) |
| `port/libgcl/*.o`  | GCL parser/compiler (loaded but not invoked at runtime) |
| `port/imgui/*.o`   | ImGui core + SDL2 + OpenGL3 backends           |
| `port/sound/`      | spu_emu, sd_init — required by `FS_LoadStageRequest` because some stage tags upload to SPU |

Editor-specific stubs (`editor_stubs.c`) provide:

- `imgui_per_pixel_light = 0`, `imgui_cam_override = 0`, etc. — globals
  `libdg_stub.o` refers to but `imgui_debug.o` would have defined
- `port_force_gouraud_neutral = 1` — switches the existing renderer to
  the unlit modulation path (every vertex's RGB is forced to 128/128/128)
- `TEST_HARNESS_*` and a few other test-server symbols
- `GM_LoadComplete = 0` (set to 1 once the editor finishes its own load)

## Camera

`ed_camera.c` keeps a float `g_cam` (pos[3], yaw, pitch, fov_scale). Each
frame `ed_camera_build_eye_inv` derives a forward direction from yaw/pitch
and calls the engine's `DG_LookAt(chanl, &eye_svec, &center_svec, h)` to
fill `DG_Chanls[1].eye_inv`. We then snapshot `eye_inv` and `clip_distance`
into `s_eye_inv` / `s_clip_dist` so HZD/actor renderers can transform world
coords to eye space without re-deriving the matrix.

Why `DG_LookAt` and not a hand-rolled matrix: matching basis handedness
to the rest of the pipeline by construction. Earlier iterations that
built the matrix from scratch shipped wrong winding (mirrored world or
upside-down) twice.

## Renderer integration

The editor never calls `port_RenderObjects` (that drives the in-game
chanl/queue pipeline). Instead, `ed_render.c::render_kmd_unlit()` walks
each model in a `DG_DEF`, projects vertices through `s_eye_inv`, and
submits triangles via `gl_submit_tri3d` directly. UVs come from
`materials[fi]` → `DG_GetTexture(hash)` → `tex->tpage/clut/off_x/off_y`.
RGB modulation is hard-coded to neutral (128/128/128), so textures
display unlit.

`gl_submit_line3d` is a small addition to `port/libdg/gl_renderer.c`
that mirrors the existing `gl_submit_tri3d` with `GL_LINES`. Used for
the world axes gizmo, HZD wireframes, actor cube markers and rotation
arrows.

## Stage discovery

`FS_StartDaemon` parses STAGE.DIR into `stage_table[]` (an array of
`{name[8], offset_in_sectors}`). After that, the editor's libfs scans
`extra_stages/`, `../extra_stages/`, `../../extra_stages/` for
`<name>/datacnf.bin` and appends synthetic entries with sentinel
`offset = 0x7FFFFFFF`. A parallel `extra_paths[]` holds the full file
path. `FS_LoadStageRequest` checks the sentinel and routes reads
through `extra_stage_read` (loose `fread`) instead of the disc image.

This is the same pattern as `port_gcl_overlay_load()` in
`port/gcl_overlay.c`, which side-loads decompiled `*.gcx` from
`overlays/<stage>/<script>.gcx`.

## Stage unload

Switching stages calls `ed_unload_stage`:

1. `GV_InitMemorySystem(GV_NORMAL_MEMORY, port_normal_memory, 2 MiB)` —
   nukes the heap, including all per-stage HZD allocations. Without
   this the 2 MiB pool fragments after two stage loads.
2. `port_fs_unload_stage` — clears the static `port_stage_info` and
   `port_current_stage`.
3. `GV_InitCacheSystem` — zeroes every cache tag.
4. `DG_InitTextureSystem` — zeroes the DG texture table so a new
   stage's `DG_GetTexture(hash)` calls don't see stale entries from
   the previous stage's PCXes (16-bit hashes can collide).
5. `memset(vram, 0, sizeof(vram))` + `gl_renderer_mark_vram_dirty(0, 512)`
   — drops the previous stage's textures and tells the GL backend to
   re-upload.

After this, `FS_LoadStageRequest` runs against a clean engine.

## Edit & save model

In-memory edits modify `g_actors[i]` directly; the renderer reads from
the same array each frame so changes are visible immediately.

`g_actors_dirty` flips on any change. `ed_actors_save` rewrites
`data/<stage>_actors.tsv` in the same 9-column layout the loader
expects, so a Reload round-trips. Deliberately *not* implemented:
writing back into `port/overlays/<stage>/scenerio.gcl` — that
round-trip lives in `port/gcl_tools/gcl_compile.py` and would belong
to a separate feature.
